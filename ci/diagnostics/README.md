# SauceDemo: изолированный PoC

Использует существующую `.venv` и Windows `OwnedProcesses`. Существующие fixtures,
Page Objects, pytest-набор и публикация Allure не подключаются.

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe ci/diagnostics/saucedemo_poc.py --mode both --repeatability
```

Сначала выполняется по одному первичному запуску на выбранный режим. Только после
их успеха `--repeatability` добавляет три последовательных независимых запуска
на режим. При первой ошибке дальнейшие запуски прекращаются; ретраев нет.

Отдельные режимы:

```powershell
.\.venv\Scripts\python.exe ci/diagnostics/saucedemo_poc.py --mode headed
.\.venv\Scripts\python.exe ci/diagnostics/saucedemo_poc.py --mode headless
```

Без `--mode` значение `HEADLESS=true` выбирает headless, иначе проверяются оба
режима. Переменная задаётся только для нужного процесса; системные настройки
Windows менять не требуется. Скрипт работает и при другом текущем каталоге,
если вызвать его и Python по абсолютным путям.

Каждая сессия получает новый временный профиль ChromeDriver. Настройки аналогичны
Web UI fixture: размер 1440x1000, отключение уведомлений, headless=new при выборе
headless, page load timeout 45 с. Явные ожидания — 15 с; полный дочерний процесс
ограничен 120 с. Закрываются только собственные процессы; личный профиль не используется.

Артефакты: новый `artifacts/saucedemo-poc-<uuid>/`, `summary.json`, `report.md`,
по одному `result.json` на запуск. Это диагностические результаты, не результаты
22 прикладных тестов и не вход для постоянной истории Allure.

При ошибке скриншот допускается только на известных страницах каталога/корзины
без полей ввода. Экран login не снимается: он содержит публичный учебный пароль.
Не сохраняются сырые исключения, HTML, browser logs, cookies и значения полей.
Наличие 403/429, challenge или CAPTCHA останавливает запуск без взаимодействия
с защитой. Учётная запись в коде — только публичная демонстрационная, указанная
на сайте. Оформление заказа не выполняется.

Ручная проверка Chrome выполняется отдельно: открыть сайт; проверить форму и
отсутствие блокировки; войти с демонстрационными данными со страницы; проверить
каталог; добавить Sauce Labs Backpack и проверить корзину. Фиксировать фактический
результат отдельно от Selenium; личные данные не вводить.

Запуск из похожего рабочего каталога и HEADLESS=true не доказывает успешность
процесса от имени службы Jenkins. Такую проверку нужно согласовывать отдельно.
