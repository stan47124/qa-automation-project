## Безопасные API-вложения

Использован разрешённый список:

- Request: метод, фиксированный BASE_URL, шаблон маршрута, timeout, допустимый status либо отметка invalid, безопасная проекция собственного Pet, размер бинарного тела.
- Response: HTTP-код, длительность, безопасная проекция собственного Pet. Для поиска — число записей, собственные Pet и количество скрытых чужих записей.
- Имена выводятся только для синтетических qa-guru-<число>/updated-<число>. Фото и теги представлены количествами; пути, URL и подписи не сохраняются.
- Headers, cookies, arbitrary query params, additionalMetadata, неизвестные JSON-поля, бинарные байты и свободный серверный текст не прикрепляются. Транспортная ошибка представлена только типом исключения.
- Автоматические stdout/stderr/log-вложения Allure отключены; исходные ошибки pytest не подавляются.

На локальных заглушках проверены Authorization/Set-Cookie, неизвестные поля с фиктивным секретом/email, чувствительные URL/текст, чужие записи и некорректный тип ID. Контрольные значения во вложения не попали. Это аудит без сетевых запросов к API. Assertions/traceback и скриншоты не являются универсальным фильтром секретов: реальные секреты нельзя вводить в тестовые данные; отчёты перед внешней публикацией требуют просмотра.

## Скриншоты при ошибках

Fixtures регистрируют только уже созданные драйверы. На failed setup/call/teardown hook пробует get_screenshot_as_png() и прикрепляет PNG к Allure. Сессия не создаётся повторно. Ошибка screenshot/attachment не заменяет исходный failure; diagnostic содержит только тип исключения.

Проверено на заглушках: два драйвера × три failed-фазы — **6 PNG-вложений**; сбой screenshot не маскирует ошибку; успешная фаза не создаёт снимок. Реальные падения приложений специально не вызывались. Android screenshot на живой сессии пока проверить нельзя. После закрытия сессии, в том числе при teardown, получение снимка не гарантируется. HTML/page_source не прикрепляются из-за возможных CSRF-токенов.

## Что запустить вручную

В терминале запустить существующий AVD без сброса данных:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -avd Pixel_4 -port 5554
```

В другом терминале — уже установленный Appium:

```powershell
appium --address 127.0.0.1 --port 4723
```

Проверить готовность:

```powershell
adb devices -l
adb -s emulator-5554 shell getprop sys.boot_completed
adb -s emulator-5554 shell cmd package resolve-activity --brief me.zhanghai.android.files
adb -s emulator-5554 shell ls -ld /sdcard/Download/qa_guru
Invoke-RestMethod http://127.0.0.1:4723/status
```

Нужны emulator-5554 в состоянии device, boot_completed=1, activity `.filelist.FileListActivity`, qa_guru и ready=true. Material Files должен иметь доступ к общей памяти; нужен английский интерфейс и UiAutomator2. Если базовой папки нет, подготовить только её без удаления данных. Исходный sample.txt не требуется. Не применять wipe-data, factory reset или очистку приложения.

После готовности — один последовательный прогон из корня:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -v
```

Allure/JUnit-пути будут созданы автоматически. Для отдельного набора заменить tests на tests/api, tests/ui или tests/mobile. Не использовать -n auto, скрытые повторы и прежние непустые каталоги. HTML Allure требует отдельно установленного CLI; его установка не выполнялась.
