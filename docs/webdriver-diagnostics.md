# Пассивная диагностика WebDriver в Jenkins

> При подготовленном возвращении Automation Exercise в Jenkinsfile задано
> `QA_WEBDRIVER_DIAGNOSTICS=`. Загруженный плагин не создаёт Monitor.
> Описанное ниже включение относится к расследованию SauceDemo, а не к
> текущей конфигурации обычной Web UI-стадии.

Диагностика предназначена для расследования нестабильного ввода SauceDemo.
Она не подтверждает устранение причины и не меняет функциональные проверки.

## Подключение и изоляция

Только Web UI-блок `Jenkinsfile` добавляет две переменные:

```groovy
"QA_WEBDRIVER_DIAGNOSTICS=${env.REPORT_ROOT}/webdriver-diagnostics",
"PYTEST_ADDOPTS=${env.PYTEST_ADDOPTS ?: ''} -p ci.diagnostics.webdriver_monitor"
```

Существующий `ci/run-web.cmd Test` остаётся без изменений. Прежнее значение
`PYTEST_ADDOPTS` сохраняется. Плагин дополнительно проверяет имя fixture
`ui_browser` и принадлежность теста каталогу `tests/ui`.

Если переменная каталога не задана или выполняется collection, плагин не
перехватывает команды, не опрашивает браузер и не создаёт файлы. API/Mobile
не инструментируются. Функциональных запусков и ретраев плагин не добавляет.

Выход: `artifacts/jenkins-<build>-<uuid>/webdriver-diagnostics/browser-<uuid>.json`.
Разрешены только каталоги внутри workspace `artifacts`; разрешённые пути
проверяются после разрешения ссылок. Файлы создаются эксклюзивно, без перезаписи.

Это соседний каталог к `api`, `web`, `mobile`. В нём нет JUnit или Allure results.
Текущие JUnit glob и список входов Allure не включают диагностику. Существующий
`archiveArtifacts` уже архивирует её через `${REPORT_ROOT}/**`. Постоянная история
не используется и не изменяется.

## Контекст процесса и браузера

После создания `ui_browser`, до первого действия сценария, собираются:

- SHA-256-псевдоним SID текущего Python-процесса, PID, SessionId и UTC timestamp;
- признак интерактивной станции окон через Win32 `UOI_FLAGS/WSF_VISIBLE`, если
  доступен; иначе `unknown`. Это не реконструкция Task Scheduler LogonType и
  не доказательство подключённой RDP-сессии;
- наличие pytest `--basetemp` и кандидата TEMP/TMP, признаки `os.access`;
  пути заменены идентификаторами. Запись в TEMP не пробуется. Эти признаки
  не объявляются полноценной проверкой эффективных Windows ACL;
- browserVersion, ChromeDriver version и ограниченный список capabilities:
  browserName, platformName, pageLoadStrategy, acceptInsecureCerts,
  setWindowRect, strictFileInteractability, unhandledPromptBehavior;
- headless из настроенной переменной и отдельный наблюдаемый признак
  `HeadlessChrome` без сохранения user-agent;
- идентификатор профиля без пути, временный шаблон имени `scoped_dir*`,
  нахождение внутри TEMP/TMP-кандидата и уникальность профиля среди сессий
  этого прогона. `isolated_temporary_profile` — совокупность этих признаков,
  а не утверждение об очистке содержимого или персональных настройках;
- фактические width/height/DPR: один read-only `execute_script` до действий
  сценария. Значения полей, DOM, URL, HTML и cookies этот запрос не читает.

Полные capabilities, переменные окружения, account name, SID и пользовательские
пути не записываются. Неизвестные/небезопасные значения отбрасываются. Ошибка
контекстного опроса не запускает повторный опрос и не должна менять результат
функционального теста. Недоступная информация остаётся `null`/`unknown`.

## Регистрация команд

Оборачивается публичный `execute` конкретного объекта WebDriver. Глобальные
классы, RemoteConnection, протокол, capabilities и параметры браузера не патчатся.

Исходный метод вызывается один раз с теми же объектами аргументов. Возвращается
тот же объект результата; исходное исключение поднимается повторно без замены.
Фиксируются только:

- порядковый номер и стандартное имя команды;
- UTC-время начала и длительность вызова;
- `ok` либо безопасный тип исключения, без сообщения/traceback;
- необязательная операция из whitelist: `checkout.first_name`,
  `checkout.last_name`, `checkout.postal_code`, `cart.checkout`,
  `checkout.continue`, `checkout.finish`.

Операция определяется по уже имеющимся `findElement`/`findChildElement` и их
возвращённому WebElement. Дополнительного поиска нет. Внутренние element IDs
используются только в памяти, не записываются. Selector допускается только
при точном совпадении с whitelist. Параметры `send_keys`, cookie/script payload,
HTTP headers, ответы сервера, значения полей и HTML не сохраняются.

Обёртка устанавливается после возврата browser fixture и действует до завершения
её teardown, включая `quit`. Создание сессии и настройка timeout до возврата
fixture не входят в журнал. Исходный метод восстанавливается после teardown;
дополнительное закрытие браузера плагином не выполняется.

Успешный ответ команды не доказывает изменение UI. Очистку и ввод можно
различать по последовательности вызовов и известному коду `CheckoutPage.fill`,
но плагин не читает клавиши для их классификации. Для фактического результата
остаются строгие проверки теста и существующая безопасная диагностика checkout.

## Тайминг и ограничения

Между взаимодействиями нет дополнительных WebDriver-команд, сетевых запросов,
пауз, повторов, JSON-сериализации или дисковых записей. События накапливаются
в памяти; JSON записывается после teardown каждой сессии.

Влияние не нулевое: добавляются Python-вызов, чтение часов, словарь и запись
в список. У traceback появляется кадр обёртки. Один viewport-запрос и чтение
метаданных выполняются до сценария. Запись файла между тестами также может
изменить общий темп прогона. Стендовые тесты контракта не измеряют это влияние
на настоящий Chrome. Данные нельзя использовать как доказательство нулевого
наблюдательного эффекта или устранения прежней гонки.

Буфер ограничен 10000 событиями на сессию; потери отмечаются
`dropped_commands`, команды при этом продолжают исполняться. Карта операций
ограничена 128 элементами. После достижения лимита новый элемент может остаться
без operation, но команда продолжит регистрироваться.

При принудительном завершении Python до teardown буфер текущей сессии может
потеряться. Фоновая запись и синхронный flush после каждой команды намеренно
не используются. Ошибки записи не создают фиктивные тесты и не меняют статусы;
в terminal summary отражается число недоступных выходных файлов. Проверять нужно
и наличие файлов, и `diagnostic_errors`/`dropped_commands` внутри них.

## Локальная проверка и следующий CI-прогон

Модульные и интеграционные проверки используют поддельный transport. Chrome,
SauceDemo, Jenkins и постоянная история при этих проверках не запускаются.
Один интеграционный тест запускает изолированный pytest с fake browser fixture
для проверки настоящего порядка hook/teardown; это не функциональный UI-прогон.

```powershell
$checkId = [guid]::NewGuid().ToString('N')
.\.venv\Scripts\python.exe -m pytest ci/tests/test_webdriver_monitor.py -q --basetemp="artifacts/monitor-unit-$checkId"
```

После отдельного разрешения на публикацию включить только плагин, его тесты,
диагностический diff Jenkinsfile и эту документацию. Poll SCM сам запустит Job.
Не нажимать Build Now и не менять расписание/Credentials.

В следующей сборке проверить SHA, исходные 22 результата, публикацию JUnit/Allure,
восемь файлов диагностики и восемь `quit`, доступность контекста SessionId/SID,
viewport и версий. Для checkout сопоставить времена `sendKeysToElement` и
`getElementProperty` с TimeoutException и вложением `Checkout field operation`.
Не трактовать `ok` как доказательство доставки input/change. При новом падении
сохранить реальные статусы, не повторять тесты и не изменять assertions.

## Отключение

После расследования удалить две диагностические строки из Web UI `withEnv`
отдельным согласованным изменением. Также достаточно убрать переменную
`QA_WEBDRIVER_DIAGNOSTICS`: загруженный плагин станет инертным. API/Mobile,
runner, fixtures, Allure и Poll SCM для отключения менять не требуется.
