## Web UI

4 ноября 2026 года сайт проверен в обычном видимом Chrome на Windows-хосте
агента, в отдельном временном профиле, без Selenium и взаимодействия со страницей
проверки. За 60 секунд приложение не появилось: URL
`https://automationexercise.com/`, title «Секундочку…», документ загружен,
маркер главной страницы отсутствует. Это подтверждает ограничение доступа к
внешнему стенду в данном окружении, но не устанавливает причину решения защиты.

При ошибке Web UI теперь прикладывается JSON состояния страницы: очищенный URL,
известный title, признаки проверки запроса, готовности документа и маркеров
приложения. Параметры URL, неизвестные пути, HTML, cookies и значения форм не
сохраняются этой диагностикой. Существующие скриншоты сохраняются как прежде.
Ошибка диагностики не заменяет исходную ошибку теста.

Дополнительное ожидание не включено: проверка не исчезла даже за 60 секунд.
После восстановления разрешённого доступа можно проверить ограниченное явное
ожидание маркера приложения (например, до 30 секунд) и отдельно отличать его от
загруженного документа. Нельзя объявлять challenge успешным открытием приложения.

Разрешённые варианты: согласовать доступ CI с владельцем Automation Exercise либо
использовать предоставленный владельцем учебный стенд. Собственный локальный
стенд потребует отдельной согласованной адаптации сценариев; он не подтвердит
работоспособность текущих восьми тестов на Automation Exercise. CAPTCHA, challenge
и антибот-защита не обходятся; assertions и статусы тестов не ослабляются.

## Mobile

Существующая подготовка сохранена: DeviceLock → запуск собственного эмулятора →
проверка загрузки Android, Package Manager и приложения → запуск собственного
Appium → ожидание `/status` → создание сессии. Готовность Android и Appium не
гарантирует готовности instrumentation. Очистка ресурсов по-прежнему выполняется
через OwnedProcesses и `driver.quit()`; чужие процессы не завершаются, данные
эмулятора и приложения не очищаются.

В capabilities явно задан `appium:uiautomator2ServerLaunchTimeout=60000` вместо
стандартных 30000 мс. Параметр поддерживается установленным UiAutomator2 Driver
8.7.3: [документация этой версии](https://github.com/appium/appium-uiautomator2-driver/blob/v8.7.3/README.md).
Это ограниченный запас для следующей проверки CI, а не доказанное устранение
причины. Ретраев сессии или тестов нет.

В №23 пять запусков достигли 30-секундного лимита, а шестой запустил сервер
примерно за 20,45 с. Единственная дополнительная диагностическая сессия после
холодного запуска 4 ноября успешно создалась: весь POST /session — 34,16 с,
интервал от `Waiting ... UiAutomator2` до определения протокола W3C — 14,32 с.
Material Files оказался активным приложением. Этот запуск подтверждает совместимость
capability и сохранность запуска, но не доказывает, что предыдущие ошибки вызваны
только недостаточным таймаутом. Длительность всего POST нельзя сравнивать напрямую
с лимитом запуска UiAutomator2. Полные шесть Mobile-сценариев здесь не выполнялись.

Каждая попытка прикладывает `Mobile: session initialization timing` с исходом,
общим временем создания сессии и лимитом сервера. При ошибке дополнительно
считываются последние 400 строк logcat с ограничением команды 10 с, без очистки
буфера. В Allure попадают только классифицированные события пакета
`io.appium.uiautomator2`: время, тип события и разрешённые типы Java-исключений
(до 80 событий), без сырых сообщений. Используется отметка времени устройства
перед попыткой; если получить её нельзя, это явно отражается в JSON. Пустой список
не доказывает отсутствие сбоя: фильтры и окно могут исключить нужное событие.

После отдельного согласования commit/push следующий запуск должен поступить
через существующий Poll SCM, без ручного запуска Job. Проверить:

1. Фактический SHA сборки и сохранение стадий API / Web UI / Mobile.
2. Отсутствие страницы проверки в Web UI; при её наличии сохранить ошибку и

4. JUnit и Allure публикуются также при ошибках; severity остаётся 12/9/1,
   группировки и механизм истории прежние. Не удалять неуспешный запуск №23.
5. Объявлять восстановление только после фактических SUCCESS и 22 passed.
