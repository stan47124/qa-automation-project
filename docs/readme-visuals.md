# Визуальные материалы для README

В репозитории пока нет снимков интерфейса Allure или реальной записи тестов.
README содержит только существующее локальное изображение технологического стека.
Ниже перечислены будущие материалы; имена файлов — план, а не ссылки на изображения.

## Снимки успешного прогона

Откройте уже завершённую успешную сборку в локальном Jenkins → Allure Report
или существующий отчёт через Allure CLI. Для общей галереи используйте один
и тот же прогон всех 22 тестов. Запускать Job специально для оформления не нужно.

| Будущее имя в `docs/assets/` | Что снять | Место в README |
| --- | --- | --- |
| `allure-overview.png` | Overview: 22 теста, итоговые статусы и время прогона | Сразу после вводного абзаца «Allure Report» |
| `allure-suites.png` | Suites с тремя наборами: API 8, Web UI 8, Mobile 6 | После Overview |
| `allure-api.png` | «Создание питомца»: POST/GET и раскрытые Request/Response (allowlisted) | После таблицы примеров, под подписью «API» |
| `allure-web.png` | «Товар, цена и количество в корзине»: шаги открытия и проверки корзины | Там же, под подписью «Web UI» |
| `allure-mobile.png` | «Copy a file»: действия с файлом и папкой назначения | Там же, под подписью «Mobile» |

После создания снимков добавьте относительные Markdown-ссылки с понятным alt.
Например, только когда файл существует:

```markdown
![Allure Overview: успешный прогон 22 тестов](docs/assets/allure-overview.png)
```

Проверьте читаемость на узком экране. Скройте персональные пути, данные аккаунта
и адресную строку, если они попали в кадр. Не меняйте цифры и статусы отчёта.

## Диагностика ошибок

PNG от hook создаётся только при ошибке активной Web UI/Mobile-сессии.
Журналы Mobile CI прикрепляются к failed/broken при наличии соответствующих
файлов. Успешный прогон не обязан содержать эти вложения.

Если появится подходящий реальный сбой, можно добавить `allure-diagnostics.png`
с раскрытым вложением после таблицы примеров. Укажите, что это другой,
неуспешный прогон, и его контекст. Не проваливайте тест специально ради картинки.

## Необязательная демонстрация

Реальную GIF или видеозапись Web UI/Mobile можно разместить в подразделе
«Визуальные материалы и демонстрация» после галереи Allure. Автоматическая
видеозапись сейчас не реализована. Для публикации подойдёт короткая ручная запись
фактического выполнения; имя, подпись и ссылка добавляются после появления файла.

## Предпросмотр

В VS Code откройте корневой README и нажмите `Ctrl+Shift+V` либо
`Ctrl+K`, затем `V` для просмотра рядом. Поддержка Mermaid зависит от Markdown
preview редактора; окончательную визуальную проверку схемы, SVG, якорей и таблиц
выполните на GitHub после согласованной публикации.
