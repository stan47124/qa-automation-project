## Структура и независимость

Один диагностический lifecycle-тест заменён восемью независимыми сценариями в `tests/api/test_petstore_smoke.py`. Имя существующего файла сохранено, но тесты больше не зависят от общего жизненного цикла.

- `tests/api/conftest.py`: отдельный requests.Session для каждого теста, уникальные данные, создание питомца и очистка.
- `tests/api/petstore.py`: базовый URL, таймаут 15 с, клиент, проверки ответов и PNG из ранее выполненного PoC.
- `tests/api/requirements.txt`: зафиксированы pytest 9.2.0, requests 2.34.2 и allure-pytest 2.16.2. Allure установлен только в `.venv`; глобальных установок не было.
- Перед использованием случайного положительного ID проверяется GET → 404. При обнаружении существующего ID тест завершается до регистрации очистки и не изменяет найденную запись.
- Cleanup регистрируется до POST. Даже при ошибке создания или проверки выполняются DELETE и контрольный GET → 404; оба запроса предпринимаются независимо, ошибки очистки отображаются как ошибки teardown.
- Все восемь тестов создают собственную запись; отрицательные запросы используют уникальные значения на основе её ID. Порядок тестов не используется для передачи состояния.
- Автоматические повторы HTTP-запросов и переходы по redirect отключены. Для каждого запроса фиксируются Allure-шаг, HTTP-статус, длительность и Content-Type. Заголовки авторизации и окружение в attachments не сохраняются.

## Документация и фактическое поведение

Изучены [Swagger UI](https://petstore3.swagger.io/), [OpenAPI 3.0.4](https://petstore3.swagger.io/api/v3/openapi.json) и `docs/poc_results.md`.

OpenAPI помечает name и photoUrls обязательными. Для uploadImage описан ApiResponse, но в обоих выполненных прогонах вернулся Pet с добавленным photoUrls. Тест проверяет это наблюдаемое поведение; формат `/tmp/...` не зафиксирован в assertions.

Отрицательные запросы предварительно проверены диагностическими GET: неверный статус и нечисловой ID действительно возвращают 400 с JSON code/message. Несуществующий питомец возвращает 404 с текстом Pet not found; поэтому для этого ответа не вызывается response.json().

## Ограничения

Во время этих прогонов нестабильность публичного Petstore не наблюдалась. Первоначальный сетевой запрет WinError 10013 был ограничением песочницы; сетевые команды выполнены после штатного разрешения. Повторы запросов для сокрытия сбоев сервера не использовались.

Petstore — общий публичный сервис: чужие изменения и перезапуски сервера могут нарушить немедленное чтение созданных записей. Набор намеренно покажет такую ошибку. Очистка проверяется для сущности Pet; отдельного endpoint удаления серверного файла изображения в изученной спецификации нет.

Mobile- и Web UI-тесты, их настройки и исходные данные не изменялись и в этой задаче не запускались.
